Every project here is something I built end to end. Each one names a standard pattern and a result you can verify. Nothing asks to be trusted; it asks to be re-run.

bfx-ingest

A zero-dependency CLI that turns a codebase into clean, deterministic LLM context in one command. On a real 1,593-file repo it produced one verifiable artifact and reported it as ~4.55M tokens, so you scope before wasting a call. Same input gives the same root hash, which makes context reproducible for evals and byte-identical for prompt caching.

  • Event sourcing · content-addressed storage
  • Deterministic, verifiable, no deps, no network
  • Tested · real benchmark included

Zero-downtime deployment system

An atomic, content-addressed release pipeline: each deploy is hashed into a verifiable manifest, promoted by an atomic symlink swap, health-checked, and automatically rolled back on failure. It replaced in-place deploys that left a site broken on partial failure with immutable releases and one-command rollback.

  • Atomic releases · health-gated auto-rollback
  • Reproducible, content-addressed manifests
  • GitHub Actions CI/CD across multiple domains

Deterministic multiplayer netcode

Real-time multiplayer where game state is derived from a seed and an append-only command log, so every client replays identical events and converges on byte-identical state. It eliminates an entire class of state-divergence bugs. Live as a playable demo at KensGames.

  • Event sourcing · deterministic lockstep
  • WebGL2 / Three.js · Node / WebSocket backend
  • Self-managed Linux VPS, PM2, nginx
Play the demo

ButterflyFx runtime

A small event-sourcing runtime: wrap any reducer and get content-addressed, hash-chained, tamper-evident state with deterministic replay. Reproducibility and auditability become architectural properties instead of afterthoughts. Each property is covered by tests.

  • Reducer in, reproducible state out
  • Hash-chained, tamper-evident log
  • Open source, tested
